Three ways to answer a call

同一通電話，三種做法

一邊是背按鍵，一邊是把任意指令交給模型。這個專案走第三條路：把「理解」和「執行」分開。

Traditional IVR

傳統按鍵 IVR

  • 來電者要記住按鍵，選單越長越容易按錯
  • 聽完整段選單才知道自己要按哪一鍵
  • 改流程就要改 dialplan，維護成本高
  • 選單外的問題完全接不住
可預測，但體驗停在二十年前。
LLM controls the PBX

讓 LLM 直接控制 PBX

  • 自然對話，但輸出不受限制
  • 模型可能生成不存在的分機或指令
  • 出錯時難以解釋，也難以重現
  • prompt 越調越長，穩定性越難保證
自由，但把交換機的入口交給了生成模型。
jev-call-router

自然語言 + 白名單

  • 來電者自然說一句話，不必記按鍵
  • Jev 只能從你定義的 routes 挑一個
  • 清單外的值判為 invalid-decision 並 fallback
  • 每通電話都有結構化結果與事件
體驗像對話，執行像 IVR 一樣可預測。
Core features

把「理解」交給模型，把「執行」留在 PBX

六個設計決定，讓自然語言分流不再是一次賭注。

自然語言分流

來電者不必聽完選單，直接說出目的。STT 轉成文字後才進入判斷，流程仍是「播放 → 錄音 → 判斷」。

選擇題式判斷

Jev 只回傳「哪一條 route」與信心分數，不生成自由文字。清單外的輸出會被直接拒絕。

三種白名單動作

只有轉接、回到 dialplan、掛斷三種。Jev 不碰 ARI、不產生 dialplan、也無法指定清單外的分機。

分層 fallback

信心不足先重問；逾時、服務中斷、聽不懂走 fallbackRoute；連續靜音可用原因碼另行改道。

直通規則優先

routeDirectly() 在 Jev 之前執行。VIP、營業時間、特定來電號碼不會被模型改寫。

可觀測性

每通電話都有 RoutingResult、SSE 事件與可選的 HMAC-SHA256 webhook，能直接送進 CRM 或 dashboard。

How a call flows

一通電話，四個步驟

從 Stasis 接手到執行轉接，每一步都只有一種工作，也都有明確的失敗出口。

01

PBX 接手通話

dialplan 用 Stasis(jev-router) 把通道交給 router，並可帶入 key=value 變數供直通規則使用。

02

播放・錄音・轉寫

播放問候、錄下來電者的話，交給任何 OpenAI 相容的 STT，或 ElevenLabs Scribe。

03

Jev 從 routes 選一條

只有寫了 description 的 route 會被提供給 Jev。回傳 route 名稱與信心分數，信心門檻預設 0.7。

04

執行動作或 fallback

達標就轉接、回 dialplan 或掛斷；任何階段失敗都走你指定的 fallback，不會落到無人接手的通道。

Stasis() 的下一行就是保底目的地：router 沒跑、連線中斷或動作失敗時，通話會回到 dialplan 的指定位置。

One config, six routes

分流規則就是一份設定檔

上面六句話對應的就是這幾條 route。改分流不需要改程式，只要改這份 config。

transfer

把通道交回 dialplan 的指定位置。

continue

從 Stasis() 的下一行繼續執行。

hangup

掛斷，可先播放一段語音。

description

只有寫了 description 的 route 才會被 Jev 看到。

Before you wire it up

適合，與不適合

這不是通用語音助理。適不適合，取決於你的來電能不能事先分類，以及你願不願意讓 PBX 保留最後的執行權。

適合這些情況

  • 已經有 Asterisk 或 FreePBX，想用自然語言取代多層 IVR
  • 來電意圖可以事先列舉，3–6 類最容易維持穩定
  • 需要 VIP、營業時間或特定號碼直通，不能被模型改寫
  • 想把每通結果送進 CRM、工單系統或 dashboard

不適合這些情況

  • 需要多輪自由對話、打斷或即時串流語音
  • 想讓模型直接執行任意 PBX 指令
  • 要求完全離線，或毫秒級延遲
  • 只想做網站 chatbot，沒有電話系統
Where it fits

四種常見的總機場景

只要是「按鍵選單已經長到沒人想聽完」的來電流程，都值得換成一句話。

01

電商客服

訂單進度、退換貨、商品諮詢、真人客服。尖峰時段大量進線，意圖卻高度集中。

「我要退貨，訂單編號 A12345」
02

SaaS 客服台

業務、技術支援、帳務與真人。同一支號碼，四種完全不同的處理流程。

「這個月發票金額好像不對」
03

中小企業總機

預約、報價、售後、櫃檯。沒有專職總機，也不需要為此多請一個人。

「請問你們過年有營業嗎？」
04

已經沒人聽完的 IVR

選單長到來電者直接按 0 找真人。把前半段換成一句話，後半段照舊。

「我要找真人客服」
